# 第一轮试玩

## 环境

Minecraft Java 客户端与服务端版本一致：26.3。启动两项服务后，在客户端“多人游戏 → 直接连接”输入 `127.0.0.1:25565`。服务端默认启用正版账户验证，绑定本机地址。

两个终端都在本仓库根目录执行：

```bash
pnpm dev:generator
```

```bash
pnpm dev:paper
```

第一次启动需要自行阅读 Minecraft EULA 并把 `var/paper/eula.txt` 中的 `eula` 设为 `true`。仅首次安装或更新 Java 插件需要重启服务器；生成的新装备通过 `/ge claim` 或管理员热加载进入已有服务器。

## 创建与使用

1. 输入 `/ge create 风的回声`。意图可以自己写，最多 10 个中文字符或英文单词；空输入允许模型自由发挥。
2. 点击材料增加数量，右键减少。当前界面明确使用**测试额度**，不会扣背包材料，也没有退款业务。
3. 点击绿色确认按钮；通过 `/ge tasks` 查询。网络超时使用 `/ge retry <任务编号>` 重试原请求；不要为了重试重新创建任务。
4. 生成完成后，输入 `/ge claim <任务编号>`。插件验证并加载装备包，然后发到背包；仅生成任务的接收人可以领取，领取后物品可正常转交。
5. 把装备放到主手，查看 `/ge inspect` 的说明和限制，再右键使用。`/ge records` 查看来历与宿主观察。

## 请反馈这些现象

| 操作 | 检查内容 |
|---|---|
| 第一次右键 | 不看代码，能否明白怎么用、作用在哪里 |
| 按说明蓄力或等待 | 画面是否对应真实阶段，等待是否有意思 |
| 故意不满足条件 | 是否说明失败原因，是否错误显示成功 |
| 发动中切换快捷栏、丢弃、入箱或退出 | 持续活动是否停止，物品的已保存能量或计数是否保留 |
| 同材料换一个意图，再生成 | 是否出现不同的机制，而不只是改名字与数值 |
| 转交给另一位玩家 | 新使用者是否读取同一物品状态，旧使用者的活动是否已停止 |

第一轮不要求每件生成装备都平衡。优先指出“做了什么、期望什么、实际看到什么”，并附任务编号或定义编号，便于关联代码和记录。

## 管理与限制

管理员可用 `/ge admin diagnose` 查看服务状态，`/ge admin load <任务编号>` 热加载已验证定义，`/ge admin disable <定义编号> <版本>` 停用异常装备。管理员权限通过服务端控制台 `op <你的玩家名>` 授予。

当前只激活主手装备。世界操作支持推力、当前伤害修改和受控伤害请求，PvP 默认拒绝。传送、地形修改、真实材料扣除、旧装备参与生成和全部库存转换尚未开放。打开库存时暂停当前装备活动，关闭后重新激活。

交付日志停在 PREPARED 或 RECOVERY_REQUIRED 时，不自动重发。管理员需要核对实际库存及日志；APPLIED/ACKNOWLEDGED 只说明曾观察到放入背包，不保证崩溃前 Minecraft 存档已刷盘。

真实客户端画面、两人联机和完整故障恢复都需要独立验收；自动测试不代表这些项目已经通过。
