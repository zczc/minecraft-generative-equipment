## 运行器实测

在本机 macOS 15.6.1、Rosetta 下的 x64 JDK 25 上，固定源程序执行 500 次。测试包含 JSON 转换、QuickJS 新上下文、一次查询和返回决策。不同冷启动轮次的 P50 约 0.15—0.22 毫秒，P95 约 1.5—2 毫秒，P99 约 3—4 毫秒。报告由测试生成在 `java/runtime-quickjs/build/reports/runtime-metrics.json`。

这些是测试程序的端到端开销，不是整个 Minecraft 游戏刻的耗时。尚不能宣称每次稳定小于 1 毫秒。宿主在 alpha2 中将每刻 5 毫秒作为停止接纳后续工作的调度目标，单次调用硬上限为 20 毫秒，每刻总硬上限为 25 毫秒。硬上限覆盖规则、查询、校验与回执处理；表现使用调度目标内的剩余时间。JVM 暂停与系统调度仍可能超过墙钟截止时间。

## 2026-11-05 客户端首次试玩

Minecraft 26.3 客户端已连接测试服，并完成真实生成装备“承重羽”的领取。首次持有时服务器停用了定义，物品状态修订仍为 0，尚未执行世界操作。离线使用同一份未改动的生成代码复现了 5 毫秒限制下的首次激活超时；一次记录约 21.5 毫秒。原日志只记异常类名，无法还原那次真实调用的具体超时位置。

修复增加了后台完整引擎预热，覆盖状态、决策转换、活动、计时器、模拟回执与表现校验；同时将调度目标和硬截止时间分开。能力清单升级为 `paper-alpha2`，使用新 profileId，允许同一宿主继续加载已验证的 alpha1 装备，仍检查原始散列、引擎与具体能力。事件和计时器失败现在统一记录事件名、游戏刻和异常堆栈。

修复后，同一份“承重羽”在 20 毫秒单次预算下连续完成四轮模拟激活、使用与 78 刻计时，每轮状态修订达到 89。18 项 Java 测试和 17 项集成测试通过；更新后的 Paper 已恢复运行，两个历史定义正常加载，生成服务确认新的预算清单。这些模拟使用内存世界，不等同于真实客户端牵引和画面验收；实际右键使用仍需玩家复测。
